# 前端课堂分析数据链路与合理性分析

> 生成日期: 2026-07-22 | 分析范围: YOLO → Pipeline JSON → FastAPI → 前端 ECharts

---

## 一、数据流全链路

```
YOLO 推理 (每 60s 窗口) → classroom_feedback_pipeline.py (analyze_delivery_package)
  → JSON v1.1 (classroom_feedback/*.json)
  → cloud_backend upload API (/api/interaction-results/with-video)
  → PostgreSQL (raw_payload JSONB)
  → FastAPI /api/teacher/results/{id}
  → dashboard_v11.py:_summary() 提取字段
  → Vue.js + ECharts 渲染
```

### 关键文件

| 层 | 文件 | 职责 |
|----|------|------|
| 分析生成 | `local_analysis_client/local-processor/core/classroom_feedback_pipeline.py` | 所有指标计算 |
| 数据模型 | `cloud_backend/schemas/interaction.py` | Pydantic 校验 V1.1 schema |
| 数据提取 | `cloud_backend/views/dashboard_v11.py:_summary()` | 从 raw JSON 提取展示字段 |
| 前端渲染 | `cloud_backend/views/dashboard_v11.py` (Vue.js inline) | ECharts 图表 + 指标卡片 |
| 报告页 | `cloud_backend/views/teacher_templates.py` | 报告中心渲染 |

## 二、各指标逐项分析

> 以下以实际 session `cls_20260721_classroom-default_c716a301414f4e449251979111f58f78` (34s, 3帧, 34s视频) 为样本。

### 2.1 专注度 (attention_score) = 82.0 — 🟡 依赖硬编码系数

**计算链：**
```
classroom_feedback_pipeline.py:2044 _resolve_avg_attention_ratio()
  → zones.front.avg_attention_ratio = 0.0  (YOLO 未产出)
  → zones.middle.avg_attention_ratio = 0.0
  → zones.back.avg_attention_ratio = 0.0
  → fallback: active_values = [1.0] (middle 区 active_ratio)
  → return round(1.0 * 0.82, 4) = 0.82     ← 🔴 硬编码魔法数字

classroom_feedback_pipeline.py:211
  → attention_score = 0.82 * 100 = 82.0
```

**问题：** 系数 `0.82` 没有任何校准依据，是在 YOLO 未产出区域专注度数据时的兜底估算。它的意思是"假设活跃的学生中有 82% 是专注的"。

**影响范围：** 当前全部 36 个 session 的 zone attention 数据均为 0，全部走这个 fallback。

---

### 2.2 响应度 (response_score) = 0.0 — ✅ 逻辑正确，展示有问题

**计算链：**
```
teacher_question_count = 0 (无 ASR 转写，无提问检测)
  → response_events = []
  → _compute_response_score([]) = 0.0
      (权重: strong=1.0, medium=0.6, weak=0.2, none=0.0)
  → _compute_response_success_rate([]) = 0.0
```

**问题不在计算，在展示。** 前端 `dashboard_v11.py` 的 `_hero_metric_rows()` 将响应度作为与专注度并列的核心卡片展示：

```python
("专注度", _score(latest.get("attention_score"))),   # 82.0
("响应度", _score(latest.get("response_score"))),    # 0.0 ← 看起来像"学生完全不响应"
```

实际原因是本地未安装 ASR 引擎（faster-whisper），导致：
- `transcript_action = "generated_unavailable"`
- `teacher_question_events = []`
- `question_guidance_summary.status = "unavailable"`

**但这不意味着"学生没有响应"——而是"系统没有数据来判断"。**

---

### 2.3 反馈分 (feedback_score) = 41.9 — 🔴 公式偏向互动，ASR 缺失时失真

**计算公式 (`classroom_feedback_pipeline.py:214-215`)：**
```python
feedback_score = (0.45 * attention_score) + (0.4 * response_score) + (0.15 * avg_activity * 100)
               = (0.45 * 82.0)     + (0.4 * 0.0)       + (0.15 * 33.33)
               = 36.9 + 0 + 5.0 = 41.9
```

**问题：** 40% 权重给响应分。当 ASR 不可用、response_score 恒为 0 时，反馈分被强制压在 40-50 区间——即使专注度有 82 分。这导致所有当前 session 的反馈分都在 41-42 分，看起来像"不及格"。

---

### 2.4 教师提问 (teacher_question_count) = 0 — 🟡 全量缺失

**数据源：**
- Pi 端: `pi_teacher_questions.py` → Vosk 离线 STT → 规则提取提问
- 本地端: `phase3_13_generate_question_events_from_asr.py` → faster-whisper ASR → 提问候选

**当前状态：** 两个 ASR 方案均未在 Windows 本地端启用：
```
transcript_error: "No runnable local ASR engine was found.
  Install one of: faster-whisper, openai-whisper, or whisper CLI"
```

全部 36 个 session 的 `teacher_question_events: []`。

---

### 2.5 响应成功率 (response_success_rate) = 0% — ✅ 逻辑正确

```
_compute_response_success_rate([]) = 0.0
```

无提问事件 → 无法计算成功率。逻辑正确，但前端展示 0% 会误导用户。

---

### 2.6 活跃度曲线 (activity_curve) — 🟡 单窗口无时序价值

**计算 (`classroom_feedback_pipeline.py:2074`)：**
```python
def _build_activity_curve(metadata, student_window_results):
    for item in student_window_results:
        zone_values = [zone["active_ratio"] for zone in item["zones"].values()]
        values.append(sum(zone_values) / len(zone_values))
    # 样本: [0.0, 1.0, 0.0] → 0.3333, 窗口数=1 → [0.3333]
```

34 秒视频 × 60 秒窗口 = **1 个窗口点**。前端 ECharts 显示一条折线图只有一个点，没有时序分析价值。

**正常情况**（如 20 分钟课堂 = 1200s / 60s = 20 个窗口）才能画出有意义的曲线。

---

### 2.7 专注度曲线 (attention_curve) — 🔴 平均值的简单重复

**计算 (`classroom_feedback_pipeline.py:2059`)：**
```python
def _build_attention_curve(metadata, student_window_results, avg_attention_ratio):
    window_count = max(1, len(student_window_results))
    return [round(float(avg_attention_ratio), 4)] * window_count
    # → [0.82]  (单窗口, 就是 avg_attention_ratio 本身)
```

当 YOLO 没有产出逐窗口专注度数据时，曲线退化为 `[avg] * N`——一条完全平坦的线，不包含任何时序变化信息。

---

### 2.8 教学阶段分布 = {exposition: 100%} — 🟡 无数据时的默认值

`_build_stage_distribution()` 依赖：
1. `teacher_question_events`（提问时间点）
2. `transcript_segments`（转写片段）

两者皆空时，返回 `{exposition_ratio: 1.0, question_ratio: 0, discussion_ratio: 0, summary_ratio: 0, management_ratio: 0}`。

前端饼图显示 100% "讲授"——技术上正确但**不表示真实的教学结构**，只表示"没有数据来分类"。

---

### 2.9 学生人数估计 (estimated_student_count) = 1 — 🔴 最低值标记

**计算 (`classroom_feedback_pipeline.py:2021`)：**
```python
def _resolve_estimated_student_count(metadata, student_window_results):
    # metadata 无 → student_window_results 有活跃区 → return 1
```

**`1` 不是真实人数估计。** 它的语义是"检测到了人类活动"，用于防止除零错误。YOLO 的 `detected_student_count_avg` 来自检测框数量除以窗口数，但实际课堂可能有 30 人，而代码没有做人数统计算法。

---

### 2.10 🔴 双评分体系混乱

同一个 session 产出两个不同的"总分"：

| 评分 | 值 | 位置 | 公式 |
|------|-----|------|------|
| `summary.feedback_score` | 41.9 | 前端核心卡片 | 简单加权: 0.45×专注 + 0.4×响应 + 0.15×活跃 |
| `score_breakdown.overall_score` | 67.03 | Phase 3.2 增强面板 | 五维评分 moving_average_3 预处理后加权 |

**前端同时展示两个不同的总分，用户会困惑"到底哪一个是真实的"。**

---

### 2.11 举手事件 (hand_raise_event_count) = 3 — 🟡 可能准确

YOLO 检测到的举手动作帧数。34 秒内 3 帧举手是可能的。但受限于 YOLO 的举手检测精度（依赖训练集覆盖情况）。

## 三、前端展示逻辑分析

### 3.1 展示范围切换 (`display_flags`)

`dashboard_v11.py:_summary()` 有一整套展示范围控制系统：

```python
asr_trusted_metrics_only = bool(
    transcript and question_events
    and (sample_type == "external_full_classroom_video_with_asr" or source_dataset == "SAV")
)
```

当 `asr_trusted_metrics_only = True` 时：
- 隐藏专注度相关指标（`hide_attention_metrics`, `hide_attention_curve`）
- 隐藏学生人数（`hide_student_count`）
- 隐藏教学阶段分布（`hide_stage_distribution`）
- 主卡片从"反馈分"切换为"ASR 互动响应"

**但这个逻辑依赖 `sample_type` 字段。** 树莓派自采数据没有设置这个字段，所以 ASR 缺失的 session 仍然走"全指标展示"路径，显示了一堆 0 值。

### 3.2 ASR 展示区

前端 `hasAsrDisplay` 计算属性检测：
- `asr_display` 字段是否存在
- `has_asr_transcript` / `has_question_events` 标记

当 ASR 数据完全缺失时，整个 ASR 展示区被隐藏——这是正确的。

### 3.3 时间线图表

专注度/活跃度/提问候选三合一图表（`renderAttentionActivityTimeline`）：
- 提问候选以散点标记在曲线上
- 当 `hideAttentionCurve = true` 时只显示活跃度
- 当专注度全为 0 时显示提示"视觉专注/热度数据不足"

**问题：** "专注度全为 0"的判断是正确的（`attentionAllZero`），但"全为 0.82"不触发任何提示——因为 fallback 给了它一个看起来合理的非零值。

## 四、问题汇总

### 🔴 严重问题

| # | 问题 | 影响 | 修复建议 |
|---|------|------|----------|
| 1 | `avg_attention_ratio` 硬编码 0.82 fallback | 专注度 82 分不可信 | 无数据时应标记为 `null` 而非估算值 |
| 2 | 双评分体系 | 用户看到两个不同的总分 | 统一为 `score_breakdown.overall_score`，废弃简单加权 |
| 3 | `estimated_student_count = 1` | 不是检测值，误导为真实人数 | 改为 `null` 或标记 `"detection_unavailable"` |

### 🟡 中等问题

| # | 问题 | 影响 | 修复建议 |
|---|------|------|----------|
| 4 | ASR 缺失时响应度显示 0.0 | 看起来像"学生不响应" | 前端区分 `0` vs `unavailable`，遮挡并标注"需安装 ASR" |
| 5 | 反馈分公式 40% 权重给响应 | ASR 缺失时分数失真 | ASR 不可用时动态调整权重或隐藏反馈分 |
| 6 | `stage_distribution` 全 exposition | 饼图无信息量 | 无数据时隐藏饼图，提示"教学阶段分析需要语音转写" |
| 7 | `attention_curve` 退化为常量 | 折线图是平的 | 标记数据来源，区分"检测值"和"推算值" |

### 🟢 低优先级

| # | 问题 | 影响 | 修复建议 |
|---|------|------|----------|
| 8 | 短视频只有 1 个窗口 | 曲线图无意义 | 至少需要 3+ 窗口才显示时序图 |
| 9 | `display_flags` 不覆盖自采数据 | 树莓派自采 session 不触发 ASR-only 模式 | 检测 `transcript_action == "generated_unavailable"` |

## 七、评分公式速查

| 评分 | 公式 | 位置 |
|------|------|------|
| `attention_score` | `avg_attention_ratio × 100` | `pipeline.py:211` |
| `response_score` | `Σ(weight × count) / total × 100` (strong=1.0, medium=0.6, weak=0.2) | `pipeline.py:2239-2249` |
| `feedback_score` | `0.45×attention + 0.4×response + 0.15×activity×100` | `pipeline.py:214` |
| `response_success_rate` | `(strong + medium) / total` | `pipeline.py:2232-2236` |
| `phase32.attention_score` | `mean(moving_avg3) - low_ratio×20 - stability_penalty` | `pipeline.py:949-955` |
| `phase32.activity_score` | `range×0.45 + peak×0.35 + continuity×0.20` | `pipeline.py:958-973` |
| `phase32.interaction_score` | `interactive_ratio×50 + event_density×30 + response×0.20` | `pipeline.py:976-988` |
| `phase32.rhythm_score` | `dominance×0.45 + attention_stability×0.35 + activity_stability×0.20` | `pipeline.py:991-1004` |
| `phase32.evidence_score` | `valid_frame_ratio×55 + video×20 + keyframe×10 + audio×15` | `pipeline.py:1007-1018` |
| `phase32.overall_score` | 五维加权 (`score_breakdown` 中的 `overall_score`) | `pipeline.py:~860` |
