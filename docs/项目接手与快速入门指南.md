## 一、 项目背景与核心架构

本系统全称为**“智能课堂行为分析与教学反馈平台”**，主要面向中小学或高校的课堂教育场景。系统旨在参加各类**计算机设计大赛或物联网设计竞赛**，以数字化评估课堂交互、提升教学质量为导向进行产品设计。

系统采用**“端（采集与对话）- 边（分析与推理）- 云（存储与大屏）”**三端协同架构：

1. **树莓派端 (`raspberry_pi_client`)**：机器人本体。运行在课室内，负责接收语音唤醒指令、与教师大模型进行自然的语音对话、触发课堂录制/音视频采集，并根据大模型意图通过 MQTT/HomeAssistant 控制外部物联网硬件设备（如灯光、窗帘）。
2. **本地分析端 (`local_analysis_client`)**：边缘计算计算节点。由于大模型和 YOLO 等视觉算法在端侧运行性能受限，本项目将高带宽的音视频分析下放到教室内或实验室的本地高性能电脑上。通过 YOLO 进行学生专注度与举手检测，使用 ASR (Whisper) 对教师提问及教学阶段进行转译融合，最终生成结构化分析 JSON。
3. **云服务器端 (`cloud_backend`)**：数据存储与管理可视化中心。接收本地端上传的分析结果，支持多教室/多班级的数据聚合。为教师提供**课堂分析详情仪表盘 (Dashboard)**，为管理员提供平台运营与设备状态监控后台。

## 三、 核心数据流与通信协议

了解这三端是如何“对话”的，对于维护系统至关重要：

```
+------------------+    局域网共享 / 脚本传输    +----------------------+    HTTP POST (JSON v1.1)    +-------------------+
| 树莓派 (本体)     | ------------------------> | 本地电脑 (AI推理端)   | --------------------------> | 云服务器 (后台展示)|
| RPi Client       |   Session 交付目录         | Local PC (Processor) |   /api/interaction-results  | Cloud Backend     |
+------------------+    +----------------------+                            +-------------------+
```

### 1. 树莓派 -> 本地电脑 (Session 交付)
当树莓派完成一次录制时，必须生成一个包含以下**四个固定命名文件**的文件夹（统称为 Session 目录）：
*   `video.mp4`：视频文件。
*   `audio.wav`：音频文件。
*   `metadata.json`：本次课堂 Session 的基本元数据（包括 `classroom_id`、录制起止时间、时长等）。
*   `teacher_transcript.json`：由树莓派端实时识别得到的教师发言文本。

### 2. 本地电脑 -> 云服务器 (数据上报)
本地分析端处理完视频与音频后，会融合视觉动作识别、语音识别结果，生成一份符合 **V1.1 协议规范**的结构化数据，通过 HTTP POST 上传：
*   **上传路由**：`POST http://<cloud-ip>:<port>/api/interaction-results`
*   **核心协议格式 (V1.1)**：参见 [schemas_v11.py](file:///D:/Codes/Python/Assitant/class-assitant-robot/cloud_backend/schemas_v11.py)。数据中包含：
    *   `schema_version`: 必须设为 `"v1.1"`。
    *   `timeline`: 包含 `attention_curve`（注意力曲线）、`heat_curve`（热力值曲线）、`activity_curve`（活跃度曲线）。
    *   `students`: 包含区域（前/中/后排）专注度与活跃度数据。
    *   `teacher`: 包含 `question_events`（提问事件数组）与 `stage_distribution`（教学环节时间占比，如讲授、提问、讨论、总结、管理等比例）。

## 四、 快速运行与调试步骤

在本地测试三端协同，可遵循以下流程：

### 步骤 1：运行云服务器端
1. **安装环境**：
   ```bash
   cd cloud_backend
   pip install -r requirements.txt
   ```
2. **初始化数据库**：
   * 本项目默认支持 PostgreSQL。如果您仅在本地轻量测试，项目支持 fallback 到 SQLite，但线上生产部署或完整功能建议使用 PostgreSQL，初始化命令：
     ```bash
     bash scripts/setup_postgres_schema.sh
     bash scripts/setup_phase2_9_auth_schema.sh
     ```
3. **启动服务**：
   ```bash
   uvicorn main:app --host 0.0.0.0 --port 8011 --reload
   ```
4. **验证**：访问 `http://127.0.0.1:8011/login`。

### 步骤 2：启动本地分析端
1. **环境依赖**：需确保安装了 PyTorch（推荐带 CUDA 支持以加快 YOLO 推理）、Loguru 以及 FFmpeg。
2. **启动监听守护进程**：
   * 在 Windows (PowerShell) 环境下，运行：
     ```powershell
     cd local_analysis_client
     ./run_local_pipeline_daemon.ps1
     ```
   * 该脚本会持续监测指定的输入文件夹，当发现新的 Session 文件夹时，会自动提取音视频并执行多模态融合管道，随后将 JSON 结构体 POST 给云端服务器。

### 步骤 3：模拟运行树莓派客户端
1. **安装依赖**：
   ```bash
   cd raspberry_pi_client
   pip install -r requirements.txt
   ```
2. **敏感配置填写**：
   * 在 [const_config.py](file:///D:/Codes/Python/Assitant/class-assitant-robot/raspberry_pi_client/const_config.py) 中，填入你个人的 SiliconFlow（大模型对话）、火山引擎/豆包、或 Azure API key。
   * 设置 `BACKEND_URL` 为你步骤 1 启动的云服务器地址。
3. **启动客户端**：
   * 启动伴随服务：`python startApi.py`
   * 
   * 启动对话服务器：`python server.py`
   * 触发视频捕获 Session（测试交付格式）：
     ```bash
     python capture_session.py start --classroom-id classroom-demo --device-id pi-demo-01
     ```

## 五、 开发规范与协作硬性约束

接手本项目进行功能修改或代码迭代时，必须严格遵守以下工程纪律（详见根目录的 [行为规则.md](file:///D:/Codes/Python/Assitant/class-assitant-robot/%E8%A1%8C%E4%B8%BA%E8%A7%84%E5%88%99.md)）：

1. **SDD（规格驱动开发）工作流**：
   > [!IMPORTANT]
   > 不要上来就直接动手修改核心代码。对于复杂的改动，应先梳理需求、修改或输出对应的 `spec`（规格文档）、`tasks`（任务清单）和 `validation`（验证标准），在逻辑闭环后再进行代码实现。
2. **数据底座的向后兼容**：
   * 本地分析端生成的 V1.1 JSON 是系统的核心数据底座。**严禁修改或破坏已有的 JSON 结构字段**。
   * 云端在查询和解析时，必须能够向下兼容可能存在缺失的旧字段（例如 `score` 与 `overall_score` 之间的转换，无筛选时 fallback 到 sample 文件等）。
3. **云端框架约束**：
   * 不要推翻重写现有的 HTML 模板与仪表盘。如果需要改进界面以应对比赛的“视觉表现力”，应当在 [ui_style.py](file:///D:/Codes/Python/Assitant/class-assitant-robot/cloud_backend/ui_style.py)、[dashboard_v11.py](file:///D:/Codes/Python/Assitant/class-assitant-robot/cloud_backend/dashboard_v11.py) 等已有框架上进行小步迭代增强。
   * 不要随意更改 PostgreSQL 数据源，除非需要适配 SQLite 轻量测试环境。
4. **开发边界**：
   * 不重构 Phase 1 已经稳定的上传链路。
   * 不重构 Phase 2 已经稳定的 Teacher API。

## 六、 比赛加分项与团队后续研发路线 (Roadmap)

如果您准备带此项目参加各种创新创业或物联网大赛，以下几个升级方向被列为高优先级的技术亮点：

*   **IoT 设备在线心跳管理**：
    *   *现状*：云端后台无法直观获知教室内树莓派和本地分析机是否正常开机。
    *   *建议*：引入 MQTT 的 Last Will (遗嘱消息) 或轻量 HTTP 心跳汇报。在云端的 Ingestion 控制台（[admin_pages.py](file:///D:/Codes/Python/Assitant/class-assitant-robot/cloud_backend/admin_pages.py)）中，添加直观的“设备在线状态指示灯”，展示设备延迟和摄像头运行状态。
*   **本地大模型 (Edge LLM) 私有化部署**：
    *   *现状*：当前树莓派交互大模型严重依赖公网 API（SiliconFlow/豆包），比赛现场网络极不稳定易导致无法演示。
    *   *建议*：在本地高性能电脑端通过 Ollama 部署轻量大模型（如 Qwen-2.5-7B-Instruct），树莓派直接将语音请求路由至局域网内的本地大模型服务，实现**完全无网/局域网离线运行交互**。
*   **“曲线-画面”时空对齐与视频回溯**：
    *   *现状*：当前 Web 端 Dashboard 仅能看到专注度曲线，视频文件虽有采集但保存在本地，无法在线播放。
    *   *建议*：打通本地端分析管道中将 `video.mp4` 压缩后自动上传至云端存储的逻辑。在教师端页面，点击专注度曲线的“低谷期”（例如第5分钟学生大量走神），可以直接在网页上播放对应第5分钟的课堂录像画面，实现多模态数据的追溯闭环。
*   **本地分析端一键化封装**：
    *   *建议*：目前本地电脑端的 YOLO 运行和 Python 监听需要手敲脚本。可以通过 PyQt5/PySide6 编写一个精美的“本地课堂AI分析工作站”桌面客户端，支持一键连接树莓派、显示 YOLO 实时识别学生（打瞌睡/举手）的标记视频画面、一键推流等，作为比赛现场演示的吸睛点。
