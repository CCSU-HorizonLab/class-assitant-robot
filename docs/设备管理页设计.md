## 一、核心策略：1 真机 + 4 虚拟

只有 1 台树莓派，但要证明架构支持横向扩展。方案：

| 设备 | 类型 | 教室 | 预期状态 | 现场展示效果 |
|------|------|------|---------|-------------|
| Pi-01 | **真实树莓派** | 301 教室 | 🟢 在线 | 现场操作：语音唤醒→录像→心跳上报，全真实数据 |
| Pi-02 | 虚拟仿真节点 | 302 教室 | 🟢 在线 | 模拟心跳，CPU 32%，展示多教室并行 |
| Pi-03 | 虚拟仿真节点 | 303 教室 | 🟢 在线 | 模拟心跳，CPU 45% |
| Pi-04 | 虚拟仿真节点 | 304 教室 | 🟢 在线 | 模拟心跳，CPU 22% |
| Pi-05 | 虚拟仿真节点 | 305 教室 | 🔴 离线 | 故意不上报心跳，展示"设备故障云端自动告警" |

虚拟节点用一段 25 行的 Python 脚本（`scripts/simulate_virtual_devices.py`），在 PC 后台跑，每 30 秒向 FastAPI 发 HTTP 心跳模拟 3 台在线 + 1 台离线。

### 答辩话术

> "出于比赛现场便携性考虑，我们接入了一台真实树莓派（Pi-01），现场所有视频采集、语音交互和心跳都是这台设备实时上报的。同时，为了验证系统横向扩展到全校多间教室的能力，平台上 Pi-02 到 Pi-05 是我们接入的集群仿真节点——包括一台模拟故障离线的 Pi-05。这证明了平台的设备管理层不仅能管好 1 台设备，更能无缝扩展到 50 间甚至 100 间教室。"

设计要点：

- **不做"重启"按钮** — 现场只有 1 台真机，点了没反应反而尴尬。页面是只读监控，操作通过 Pi 端本地执行。如果评委问"能远程控制吗？"，回答"架构预留了 MQTT 指令下发通道，当前版本聚焦监控与告警"
- **告警区单独一行** — 离线设备高亮提醒，这是 IoT 平台的标准功能，比单纯列表更有"平台感"
- 每 5 秒自动刷新（前端轮询），让评委看到心跳时间在跳

## 三、数据模型

```sql
-- 设备表（云数据库）
CREATE TABLE devices (
    id              SERIAL PRIMARY KEY,
    device_name     VARCHAR(100) NOT NULL,         -- Pi-01
    device_mac      VARCHAR(17) UNIQUE,            -- b8:27:eb:xx:xx:xx
    classroom_name  VARCHAR(100),                   -- 301教室
    ip_address      VARCHAR(45),                    -- 192.168.31.124
    device_type     VARCHAR(20) DEFAULT 'real',     -- 'real' | 'virtual'
    device_status   VARCHAR(20) DEFAULT 'offline',  -- 'online' | 'offline'
    last_heartbeat  TIMESTAMP,                      -- 最后心跳时间
    cpu_percent     REAL DEFAULT 0,
    mem_percent     REAL DEFAULT 0,
    disk_percent    REAL DEFAULT 0,
    temperature     REAL,
    capture_count   INTEGER DEFAULT 0,
    is_active       BOOLEAN DEFAULT true,
    registered_at   TIMESTAMP DEFAULT NOW(),
    updated_at      TIMESTAMP DEFAULT NOW()
);
```

`device_type` 字段区分真实设备和虚拟仿真节点，答辩时可以说明哪些是真机、哪些是集群仿真。

## 四、心跳通道设计（MQTT + HTTP 双通道降级）

```
Pi 端心跳 (每 30s)
  │
  ├── 1️⃣ 尝试 MQTT publish ──▶ Mosquitto Broker ──▶ FastAPI MQTT Listener ──▶ UPDATE devices
  │    (主通道，轻量级，符合 IoT 规范)
  │
  └── 2️⃣ MQTT 异常时降级 ──▶ HTTP POST /api/device/heartbeat ──▶ 直接 UPDATE devices
       (保底通道，保证比赛时万无一失)
```

### 4.1 Pi 端心跳脚本（带降级逻辑）

```python
# raspberry_pi_client/device_heartbeat.py (~60行)
import json, time, uuid, socket
import requests
import psutil

BROKER_HOST = "192.168.31.22"
BROKER_PORT = 1883
HEARTBEAT_URL = "http://192.168.31.22:8011/api/device/heartbeat"
DEVICE_MAC = ':'.join(['{:02x}'.format((uuid.getnode() >> ele) & 0xff)
                       for ele in range(0,8*6,8)][::-1])

def get_system_info():
    return {
        "device_mac": DEVICE_MAC,
        "device_name": "Pi-01",
        "cpu_percent": psutil.cpu_percent(interval=1),
        "mem_percent": psutil.virtual_memory().percent,
        "disk_percent": psutil.disk_usage('/').percent,
        "temperature": _read_cpu_temp(),
        "timestamp": int(time.time())
    }

def send_via_mqtt(payload):
    """主通道：MQTT publish"""
    import paho.mqtt.client as mqtt
    client = mqtt.Client()
    client.connect(BROKER_HOST, BROKER_PORT, 60)
    client.publish("classroom/device/heartbeat", json.dumps(payload), qos=1)
    client.disconnect()

def send_via_http(payload):
    """降级通道：HTTP POST"""
    requests.post(HEARTBEAT_URL, json=payload, timeout=5)

def main():
    while True:
        payload = get_system_info()
        try:
            send_via_mqtt(payload)
        except Exception:
            # MQTT 连不上 → 自动降级为 HTTP
            try:
                send_via_http(payload)
            except Exception:
                pass
        time.sleep(30)

if __name__ == "__main__":
    main()
```

### 4.2 虚拟仿真节点脚本（PC 端后台运行）

```python
# scripts/simulate_virtual_devices.py (~25行)
import requests, time, random

VIRTUAL = [
    {"device_mac": "b8:27:eb:00:00:02", "device_name": "Pi-02", "classroom_name": "302教室"},
    {"device_mac": "b8:27:eb:00:00:03", "device_name": "Pi-03", "classroom_name": "303教室"},
    {"device_mac": "b8:27:eb:00:00:04", "device_name": "Pi-04", "classroom_name": "304教室"},
    # Pi-05 不在此列表 → 不发送心跳 → 自动变离线
]

while True:
    for dev in VIRTUAL:
        try:
            requests.post("http://localhost:8011/api/device/heartbeat", json={
                "device_mac": dev["device_mac"],
                "device_name": dev["device_name"],
                "classroom_name": dev["classroom_name"],
                "device_type": "virtual",
                "cpu_percent": round(random.uniform(20, 50), 1),
                "mem_percent": round(random.uniform(30, 55), 1),
                "disk_percent": round(random.uniform(25, 45), 1),
                "temperature": round(random.uniform(40, 52), 1),
                "timestamp": int(time.time())
            }, timeout=5)
        except Exception:
            pass
    time.sleep(30)
```

### 4.3 云端心跳超时自动离线检测（FastAPI 后台任务）

```
隐患：Pi 突然断电 → 不会主动发"离线"消息 → DB 一直显示 online
解决：FastAPI 启动时注册一个后台定时任务，每 30 秒扫描一次
      如果 last_heartbeat > 90 秒 → 自动标为 offline
```

```python
# cloud_backend/routers/device.py 中的后台任务
import asyncio

async def heartbeat_timeout_checker(interval: int = 30, timeout: int = 90):
    """后台任务：扫描 devices 表，超过 timeout 秒无心跳的标为 offline"""
    while True:
        await asyncio.sleep(interval)
        try:
            conn = _get_conn()  # psycopg2 connection
            with conn.cursor() as cur:
                cur.execute("""
                    UPDATE devices
                    SET device_status = 'offline'
                    WHERE device_status = 'online'
                      AND last_heartbeat < NOW() - INTERVAL '%s seconds'
                """, (timeout,))
                updated = cur.rowcount
                if updated > 0:
                    cur.execute("COMMIT")
                    logger.info("Auto-offline: %s device(s) marked offline", updated)
            conn.close()
        except Exception as e:
            logger.warning("Heartbeat checker error: %s", e)
```

在 `main.py` lifespan 中注册：

```python
@asynccontextmanager
async def lifespan(_: FastAPI):
    # ... 现有启动逻辑 ...
    task = asyncio.create_task(heartbeat_timeout_checker())
    yield
    task.cancel()
```

## 五、后端 API 设计

### 5.1 心跳上报（设备 → 云端）

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/device/heartbeat` | 设备（真实/虚拟）上报心跳 |

心跳数据 `{device_mac, device_name, classroom_name, device_type, cpu, mem, disk, temperature, timestamp}`

处理逻辑：
1. 按 `device_mac` 查找 → 存在则更新 CPU/内存/磁盘/温度/心跳时间/状态为 online
2. 不存在 → 自动注册（device_name + classroom_name 来自心跳包，device_type 标记 real/virtual）
3. 物理外设状态（摄像头、麦克风是否可用）不上报（当前架构 Pi 端不采集这些外设状态，不做假数据）

### 5.2 管理端查询

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/admin/devices` | 设备列表 + 统计摘要（总数/在线/离线/运行率） |
