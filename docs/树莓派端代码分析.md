## 二、核心链路

```
唤醒 (Snowboy) → chat.py:work() → speechpoint.record() 收音
  → voice_solution → Azure STT (reco.py)
  → prompt_and_deal.py → SiliconFlow DeepSeek-V3 (deepseek_chat_stream.py)
  → voice_solution → Azure TTS (tts_stream.py)
  → play.py 播放
```

**课堂录制子链路 (比赛核心)：**

```
Flask /api/capture/start → pi_capture_runtime.start()
  → cv2.VideoCapture + pyaudio 采集
  → Flask /api/capture/stop → pi_capture_runtime.stop()
  → video_standardizer.standardize_video() → ffmpeg H.264
  → pi_transcript_delivery.build_teacher_transcript()
  → pi_teacher_questions.build_teacher_questions()
  → 打包 metadata.json + video.mp4 + audio.wav → captures_local_delivery/ (CIFS 挂载点)
```

### 3.2 备选语音方案（2 套, ~1,040 行）🟡 非死代码，是完工的切换方案

| 方案 | 文件 | 行数 | 状态 |
|------|------|------|------|
| Doubao 语音 | `Doubao_solution/` | 952 | 🟡 **已完工的备选方案**，一行配置即可切换 |
| 本地 TTS | `local_tts/` | 88 | 🟡 离线回退方案 |

`voice_solution.py` 的设计就是三选一路由：

```python
voice_solution = 'azure'   # 当前使用
# voice_solution = 'doubao'  # 改这一行即可切换
# voice_solution = 'local'   # 离线回退
```

**Doubao 方案不应归档**。它是一套完整的 WebSocket 流式 TTS 协议栈（`protocols.py` 549 行 = 二进制帧协议定义 + 连接管理 + session 生命周期），代码质量高，切换成本为零。保留理由：
- Azure 免费额度可能在比赛密集测试时耗尽
- 豆包国内服务，中文语音识别可能更优、延迟更低
- 比赛现场 Azure 故障时的即时回退方案

## 七、安全风险

CLAUDE.md 中明确写了 **"const_config.py（含 API key，不要覆盖）"**，说明 Pi 真机上的文件与 repo 中的不同。
