# 端边云协同的智慧课堂感知与评价系统 - 系统设计说明书

## 一、 系统总体架构设计

本系统基于物联网的“感知、网络、平台、应用”四层体系，针对高吞吐量视频推理和隐私安全要求，设计了**“端—边—云”三层协同拓扑架构**。

```text
+-----------------------+              局域网共享目录             +-----------------------+
|  感知感知端 (Pi Node)  | =====================================> | 边缘计算端 (Edge PC)   |
|  - 音视频录制与硬转码  |           Session 交付共享             | - YOLOv8 行为检测推理  |
|  - 本地语音唤醒与控制  | (video.mp4/audio.wav/metadata.json)   | - Vosk 教师提问分析    |
+-----------------------+                                         +-----------------------+
            ||                                                                ||
            || 周期性设备状态心跳                                               || 批量分析结果上传
            || (MQTT 双通道心跳, 30s)                                         || (HTTP POST v1.1 JSON)
            \/                                                                \/
+-----------------------------------------------------------------------------------------+
|                                云端协同管控层 (Cloud Backend)                           |
|  - FastAPI 后台 & 状态监测服务                                                           |
|  - PostgreSQL 数据库 (持久化结果)                                                       |
|  - 教师工作台 Dashboard & 管理员控制台                                                  |
+-----------------------------------------------------------------------------------------+
```

### 1. 树莓派感知端 (RPi Client)
部署在课室前侧，配置 USB 广角摄像头与高灵敏麦克风，负责原始音视频的高清捕获，运行 Snowboy 离线唤醒实现极速本地录制触发。通过 CIFS/SMB 协议将媒体文件就地写入局域网共享存储，不执行高负载 AI 分析。

### 2. 边缘计算端 (Edge Analyzer)
部署在课室本地局域网内的高性能分析主机，运行 Windows/Linux 系统，配置 Nvidia GPU 并支持 CUDA。守护进程自动轮询共享存储，当检测到新 Session 目录时，并行调起 YOLOv8 检测进程与 Vosk 音轨识别进程，将分析结果规整为结构化 JSON 报告后通过公网上传。

### 3. 云服务器端 (Cloud Backend)
部署在阿里云公网节点，运行 FastAPI 框架与 PostgreSQL 14 数据库。云端仅接收结构化 JSON 报告，不留存视频本体，在保障隐私的前提下呈现多维大屏。云端同步维护一个后台进程，监测各节点上报的心跳，并提供设备超时离线报警。

## 二、 核心子系统详细设计

### 1. 树莓派感知采集端
*   **交互枢纽 (`server.py`)**：树莓派端的主服务，包含设备初始化、MQTT 客户端长连接、以及人机对话线程的管理。
*   **录制控制 (`capture_session.py`)**：在接收到“开始/停止录影”的控制信号后，调用 OpenCV 捕获视频流，使用 PyAudio 采集音频流。通过 FFmpeg 对视频进行 H.264 硬件转码封装，降低视频体积至约 50MB - 200MB 之间。
*   **心跳监控 (`heartbeat_reporter.py`)**：包含系统状态采集引擎，利用 `psutil` 读取 CPU 温度、内存使用率、磁盘占用，按 30 秒周期向云端推送心跳包。

### 2. 边缘智能分析端
*   **本地管道守护进程 (`run_local_pipeline_daemon.ps1`)**：每 15 秒扫描一次交付目录，维护分析任务的队列，调用 Pipeline 进行自动计算。
*   **多模态融合管道 (`classroom_feedback_pipeline.py`)**：
    *   **视觉行为分析**：将录像文件抽样提取关键帧，通过封装的 `YOLOv8` 目标检测器预测“低头听讲”、“举手发言”、“站立”等动作，生成注意力与活跃度曲线。
    *   **语音分析**：加载 `Vosk` 离线模型转写音频，标定教师问答的时间区间，通过规则引擎识别问句并划定课堂讨论阶段占比。
    *   **五维评分模型**：融合五维权重参数，输出每堂课的最终评估报告。

### 3. 云端协同管控端
*   **接收路由 (`routers/device.py`, `routers/ingestion.py`)**：暴露 `/api/device/heartbeat` 和 `/api/interaction-results` 端点，对传入的 JSON 进行 Pydantic 协议合法性校验。
*   **仓储层服务 (`services/postgres_service.py`)**：负责操作 PostgreSQL，支持设备表的 Upsert 更新以及课堂数据的关联写入。
*   **超时检查服务**：内置守护任务 `_heartbeat_timeout_checker`，循环检测 `device` 表，凡 `last_heartbeat` 超过 90 秒未更新的设备，一律自动标记为 `offline` 并抛出告警。

## 三、 通信协议与数据格式规范

### 1. 树莓派 -> 边缘分析端 (Session 目录结构)
录制结束后，树莓派在局域网 CIFS 存储中生成的 Session 目录包含以下文件：
*   `video.mp4`：经过 H.264 编码的 MP4 格式视频文件。
*   `audio.wav`：16KHz, 16bit, 单声道 PCM 格式音频。
*   `metadata.json`：包含 `classroom_id`、录制开始时间、录制时长等基础元数据。
*   `teacher_transcript.json`：树莓派端实时识别的初步发言字幕。

### 2. 边缘分析端 -> 云端 (V1.1 JSON 协议数据结构)
数据推送至 `POST /api/interaction-results`，其核心 Schema 定义如下：

## 四、 数据库表设计 (PostgreSQL)

云服务器端存储采用关系型结构，核心物理模型设计如下：

### 1. 设备状态表 (`devices`)
用于持久化集群中各端侧采集设备的健康数据及联网状态。
```sql
CREATE TABLE devices (
    device_mac VARCHAR(50) PRIMARY KEY,     -- 物理MAC地址，唯一主键
    device_name VARCHAR(100) NOT NULL,      -- 设备代号
    classroom_name VARCHAR(100),            -- 绑定教室名称
    device_status VARCHAR(20) DEFAULT 'offline', -- online/offline 状态
    cpu_percent REAL,                       -- 最近上报CPU率
    mem_percent REAL,                       -- 最近上报内存率
    disk_percent REAL,                      -- 最近上报磁盘率
    temperature REAL,                       -- CPU温度
    last_heartbeat TIMESTAMPTZ,             -- 上次心跳时间
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2. 课堂分析结果表 (`classroom_results`)
用于存储每次 Session 的高维度分析结果，为教师大屏提供数据源。
```sql
CREATE TABLE classroom_results (
    analysis_id VARCHAR(100) PRIMARY KEY,   -- 分析流水唯一ID
    classroom_id VARCHAR(100) NOT NULL,     -- 教室编码
    video_id VARCHAR(100),                  -- 关联视频ID
    recorded_at TIMESTAMPTZ NOT NULL,       -- 摄像头发起录制时间
    duration_seconds REAL NOT NULL,         -- 录制时长 (秒)
    feedback_score REAL,                    -- 五维综合反馈评分
    attention_score REAL,                   -- 注意力评分
    response_score REAL,                    -- 响应度评分
    avg_attention_ratio REAL,               -- 平均注意力比例
    teacher_question_count INT,             -- 教师提问次数
    summary_text TEXT,                      -- AI生成的总结文本
    timeline_data JSONB,                    -- 存放注意力/热力/活跃度曲线数组
    created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_classroom_recorded_at ON classroom_results (recorded_at DESC);
```

## 五、 容灾与稳定性设计

### 1. 本地磁盘缓存与重试机制
若公网发生中断，边缘分析端产生的 V1.1 JSON 报告将自动被放入 `processed_results/pending_upload` 本地挂起目录中。守护进程会将其标记为“待补传”。在网络恢复后，守护进程会读取挂起目录，在 3 次重试限制内自动重新发起 POST 补传，直到云端成功返回 `success: true`，方才移动至归档目录，防止数据丢失。

### 2. 心跳双通道自动降级
树莓派端集成了双通道上报客户端。默认状态下，上报主信道为 **MQTT 协议**，由于其长连接、轻量性，网络压力极小。当 MQTT 连接由于断网或 Broker 挂起发生连续失败时，客户端会自动触发**降级机制**，切换为基于公网 **HTTP POST 短连接**上报健康指标。网络链路恢复后，系统会自动升级并切回主通道 MQTT，确保管理员对终端节点的可观测性。
