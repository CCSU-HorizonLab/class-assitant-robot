## 三、⚠️ 向后兼容包装层 — 不是死代码，是当前生产导入链的核心

### 3.1 现状：包装器是生产环境的必经之路

根目录的 5 个文件不是死代码。它们是当前 `sys.path` + `importlib` 导入链的**关键桥接层**。

**完整导入链：**

```
consume_ready_sessions.py:12-14
  REPO_ROOT = Path(__file__).resolve().parents[2]    # = local_analysis_client/
  sys.path.insert(0, str(REPO_ROOT))                 # ← 将 local_analysis_client/ 注入搜索路径

    ↓ from classroom_feedback_pipeline import analyze_delivery_package (绝对导入)

  Python 在 sys.path[0] 中查找
    → 命中 local_analysis_client/classroom_feedback_pipeline.py  ← 包装器 stub
    → importlib 动态加载 local-processor/core/classroom_feedback_pipeline.py  ← 真实代码

    ↓ 真实代码内部: from yolo_interaction_processor import ... (绝对导入)

  Python 再次在 sys.path[0] 中查找
    → 命中 local_analysis_client/yolo_interaction_processor.py  ← 包装器 stub
    → importlib 动态加载 local-processor/core/yolo_interaction_processor.py  ← 真实代码
```

**关键事实：**

| 事实 | 说明 |
|------|------|
| `local-processor/` 不是 Python 包 | 零个 `__init__.py`，无法用 `from local_processor.core.xxx import` |
| `sys.path.insert(0, ...)` | `consume_ready_sessions.py` 第 13-14 行强制注入 |
| 绝对导入 | `classroom_feedback_pipeline.py:19` 使用 `from yolo_interaction_processor import` |
| `globals()` 全量注入 | 包装器的 `globals()[_name] = getattr(...)` 使 IDE 完全无法跳转 |

```python
# 包装器的核心逻辑（5 个文件完全相同）
def _load_relocated_module():
    module_path = Path(__file__).resolve().parent / "local-processor" / "core" / "classroom_feedback_pipeline.py"
    spec = importlib.util.spec_from_file_location("...", module_path)
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    return module

_MODULE = _load_relocated_module()
for _name in dir(_MODULE):
    if _name.startswith("_"):
        continue
    globals()[_name] = getattr(_MODULE, _name)   # ← IDE 和静态分析工具完全不可见
```

### 3.2 不能在清理其他死代码之前直接删除包装器

如果直接删除 `local_analysis_client/*.py` 这 5 个文件，会导致：

1. `consume_ready_sessions.py` 的 `from classroom_feedback_pipeline import ...` 抛出 `ModuleNotFoundError`
2. `classroom_feedback_pipeline.py` 的 `from yolo_interaction_processor import ...` 抛出 `ModuleNotFoundError`
3. 整个本地分析链路崩溃

### 3.3 解除依赖的正确方案

**必须先做这一步，再做其他清理：**

#### 步骤 A：将 `local-processor` 变成真正的 Python 包

```bash
cd local_analysis_client/local-processor
touch __init__.py
touch core/__init__.py
touch api/__init__.py
touch scripts/__init__.py
```

#### 步骤 B：核心模块内部改用相对导入

在 `local-processor/core/classroom_feedback_pipeline.py` 第 19 行：

```python
# 改前（绝对导入，走 sys.path → 包装器）
from yolo_interaction_processor import (
    build_default_processor,
    load_processor_config,
    resolve_config_path,
    validate_result_payload,
)

# 改后（相对导入，同目录直接引用）
from .yolo_interaction_processor import (
    build_default_processor,
    load_processor_config,
    resolve_config_path,
    validate_result_payload,
)
```

#### 步骤 C：消费脚本改用包路径导入

在 `local-processor/scripts/consume_ready_sessions.py`：

```python
# 改前
REPO_ROOT = Path(__file__).resolve().parents[2]
if str(REPO_ROOT) not in sys.path:
    sys.path.insert(0, str(REPO_ROOT))             # ← 删除这两行
from classroom_feedback_pipeline import analyze_delivery_package  # ← 改掉

# 改后
from ..core.classroom_feedback_pipeline import analyze_delivery_package
```

#### 步骤 D：验证并删除包装器

```bash
# 确认所有导入走包路径后，删除 5 个包装器 stub
cd local_analysis_client
git rm classroom_feedback_pipeline.py
git rm yolo_interaction_processor.py
git rm keyframe_receiver.py
git rm build_interaction_dataset.py
git rm train_interaction_model.py
```

**收益：**
- 消除 `sys.path` 污染
- 消除 `globals()` 注入，IDE 可正常跳转和重构
- 消除 5 个包装器文件的维护负担
- 消除整个 `importlib` 动态加载层的运行时开销
