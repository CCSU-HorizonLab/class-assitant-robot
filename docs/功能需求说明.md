# 端边云协同的智慧课堂感知与评价系统 - 功能需求说明书

## 一、 系统角色定义

本系统主要服务于学校教育场景中的两类核心用户：

### 1. 教师（教学主体）
教师是教学活动的设计者与执行者。系统为教师提供客观的数据反馈，帮助其进行课堂复盘与教学改进。主要需求包括：
*   **自然便捷的交互方式**：在课中无需复杂的手动操作，通过语音对话即可控制设备的录制，不干扰正常教学秩序。
*   **多维度的课堂感知分析**：能够直观地看到整节课中学生的注意力波动曲线、活跃状态以及前中后排的听课差异。
*   **客观的教学表现评估**：了解自身在课堂中的提问频次、问题类型以及讲解与讨论的时间分配比例（教学环节分布）。
*   **结构化的课堂反馈报告**：每节课后自动生成包含综合评分、关键事件时间线及教学反思建议的报告。

### 2. 系统管理员（运维主体）
管理员负责维护全校多个教室内设备集群的正常运转与数据同步。主要需求包括：
*   **设备在线状态监控**：实时掌握各个教室树莓派采集端、本地分析机节点的联网状态与运行指标（如CPU温度、磁盘容量）。
*   **异常自动告警**：在采集终端离线、硬件故障或数据传输中断时，能第一时间接收到系统的告警提示。
*   **接入数据流向追踪**：能够查看数据接收历史，掌握哪些数据已成功入库，哪些正在处理或处于重试阶段。

## 二、 核心功能模块划分

系统功能设计紧密围绕“感知-分析-展示”的闭环，分为以下三大核心模块：

### 1. 感知采集与语音交互模块（端侧 - 树莓派端）
部署在教室内，作为物理世界的“眼睛”和“耳朵”，负责数据获取与人机交互：
*   **离线语音唤醒**：在本地运行轻量化语音唤醒引擎，支持唤醒词“晓晓”，被动监听唤醒指令。
*   **大模型自然对话**：唤醒后支持大语言模型对话，教师可与机器人进行自然的教学内容交流或获取教学信息。
*   **音视频同步录制**：支持通过特定语音指令（如“开始录像”/“停止录像”）直接触发本地摄像头与麦克风进行音视频采集，并按要求转码为兼容浏览器的播放格式。
*   **Session 封装与交付**：录制结束后，自动将生成的视频、音频、基础元数据（开始/结束时间、时长等）和实时生成的语音文本封装进统一的 Session 目录，并投递至本地共享存储中。
*   **心跳上报**：周期性（30秒）采集设备硬件状态（如温度、内存），并上报至云端。

### 2. 边缘 AI 行为检测与转译模块（边侧 - 边缘分析机）
部署在学校机房或教室内的高性能计算机中，负责消耗高算力的本地推理与多模态分析：
*   **自动监听与消费**：守护进程以 15 秒为周期检测共享存储区，一旦发现未处理的 Session 目录，即自动拉起处理流程。
*   **学生行为检测（视觉）**：调用 YOLO 模型对视频文件进行推理，检测学生低头、举手、站立等动作，按滑动窗口统计得出时间序列曲线与前中后排的区域专注度。
*   **教师提问提取（语音）**：通过 ASR 引擎转译音频，利用规则引擎分析提问文本，标定提问发生的时间戳并识别提问类型（如开放性或封闭性问题）。
*   **多模态指标拟合**：将视觉和语音分析结果，输入到“五维综合课堂评分模型”中，计算得出该节课的综合评分，生成符合 V1.1 协议的结构化数据报告。
*   **数据自动上报**：通过 HTTP POST 接口，自动将结构化报告及压缩后的关键帧数据推送至云端。

### 3. 云端数据管理与可视化大屏（云侧 - 云服务器）
部署在公网云端，作为全局中心，负责数据持久化、界面展示与集群运维：
*   **统一安全登录**：教师和管理员通过统一入口登录，系统根据账号角色自动路由分流至不同的工作台。
*   **教师工作台（可视化大屏）**：
    *   **今日课堂总览**：展示今日上课的总体指标卡片（如平均专注度、活跃度）。
    *   **课堂记录列表**：分页显示历史授课录像，支持按班级、日期筛选，视频可在线流畅回放。
    *   **课堂分析详情**：以图表形式展示多维课堂评分（注意力、活跃度、互动率等）、专注度波动折线图、教学阶段分布饼图、提问事件轴以及教学建议摘要。
*   **管理员控制台（运维管理）**：
    *   **设备监控大屏**：直观展示全校采集终端的实时 CPU 占用率、温度、内存和磁盘空间，提供状态指示灯。
    *   **离线告警中心**：超过 90 秒未收到设备心跳时，自动将状态标红并记录告警。
    *   **数据上报日志（Ingestion Status）**：展示本地分析端每次数据推送的状态、数据大小、延迟时间及失败重试历史。

## 三、 业务流程与使用场景

系统在日常教学中的典型运行逻辑如下：

```text
 课前准备              课中教学（端）                课后分析（边）              数据复盘（云）
+----------+        +------------------+        +-------------------+        +-------------------+
| 设备自检 | ------> | 语音唤醒触发录制 | ------> | 本地机房自动分析  | ------> | 云端生成大屏报告  |
| 周期心跳 |        | 硬件音视频采集   |        | YOLO行为 + 提问 ASR|        | 教师/教务复盘教学 |
+----------+        +------------------+        +-------------------+        +-------------------+
```

### 1. 课前：设备就绪与状态监测
每日清晨，教室内树莓派和边缘分析机开机。树莓派自动启动心跳服务，每 30 秒上报一次健康数据；云端“心跳监测守护进程”持续扫描接收，管理员通过控制台确认所有设备均正常在线（绿灯）。

### 2. 课中：语音控制与智能采集
上课后，教师无需走到讲台前操作电脑，只需站在讲台上说出：“晓晓，开始录像”，机器人端侧收到指令，本地立即调起摄像头与麦克风开始双路同步录音录像。下课时，教师发出：“晓晓，停止录像”，设备停止捕获。

### 3. 课后：全自动数据处理与流传
录像结束后，树莓派将录制文件打包成标准 Session 输出到共享文件夹中。边缘端的守护进程检测到新包，自动调用 YOLO 进行学生交互行为预测，调用 Vosk/Whisper 对音频进行语音解析，得出专注度与提问曲线，并打包成 100KB 的 JSON 报告 POST 给云服务器，整个过程无需人工干预。

### 4. 离线/弱网场景容灾
若学校校园网与云服务器之间断网，树莓派仍然能正常进行本地语音唤醒和视频录制，边缘分析机仍能在局域网内完成行为检测。分析产生的 JSON 报告会保存在本地待发送队列中。一旦网络恢复，守护进程将自动重试并补传数据，确保数据链闭环与数据不丢失。
